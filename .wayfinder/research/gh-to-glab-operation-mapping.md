# gh -> glab / GitLab API operation mapping (gitlab.com Free)

Ticket: `.wayfinder/tickets/002-gh-to-glab-operation-mapping.md`. Researched 2026-11-04.
Sources: docs.gitlab.com/cli/* (glab reference) and docs.gitlab.com/api/*, /user/*. Each row cites its page.
Marks: **[doc]** = stated on the cited page. **[inferred]** = my reasoning, not stated in docs; verify before relying on it. **[not verified]** = page did not cover it.

Base URLs: CLI `https://docs.gitlab.com/cli/`, API `https://docs.gitlab.com/api/`.
Vocabulary: GitHub PR number = GitLab MR `iid` (`!123`); issue `#123` stays `#123`. REST path uses `projects/:id` (numeric ID or URL-encoded `group%2Fproject`); `glab api` fills `:fullpath`/`:id` from the cwd repo (`/cli/api/`).

## 1. What super-board actually uses (grep of skills/ scripts/ hooks/ workflows/)

- `gh issue`: view, edit (`--add-label/--remove-label/--add-assignee/--remove-assignee`), comment, list (`--state`, `-l`, `--assignee`, `--json`), create, close (`--reason`).
- `gh pr`: create (`--draft --base --head --title --body-file`), view (`--json`), merge (`--squash --delete-branch --match-head-commit`, `--auto`), ready, edit, diff, comment, list (`--state merged --search`), checks.
- `--json` fields: `number,title,body,labels,url,stateReason,headRefName,headRefOid,baseRefName,files,additions,deletions,changedFiles,comments,state,mergeCommit,nameWithOwner,owner,defaultBranchRef,assignees`.
- `gh api`: `repos/{o}/{r}/issues/<N>[/comments|/labels]`, `issues/comments/<id>` (PATCH), `pulls/<N>[/files]`, `commits/<sha>/check-runs`, `rate_limit`, `user`, `graphql` (resolveReviewThread, project v2 items), `--input`, `--paginate`.
- `gh repo view --json owner|nameWithOwner|defaultBranchRef`; `gh auth status|login|refresh -s project,read:project,repo|switch`; `gh label create|edit|list|delete`; `gh project *` (Projects v2).
- Raw image URLs: `https://github.com/<owner>/<repo>/raw/<sha>/<path>`.
- Closing refs: `Closes #N` in PR body/commit; `Refs #N` for partial.

## 3. Cross-cutting gaps (ranked)

1. **Projects v2 board** has no Free-tier equivalent (see row). Needs design decision.
2. **No `--json field,field` selector** in glab: output is the whole API object; use `--jq`. JSON key names are API snake_case, not gh camelCase. Build a thin adapter (`number`<-`iid`, `url`<-`web_url`, `headRefOid`<-`sha`, ...). Note: glab json output is the API-shaped object [inferred; confirm with a live `glab mr view -F json`].
3. **Close reason** (`stateReason`) absent.
4. **Auto-closing** only on default-branch merge; non-default base_branch needs explicit close.
5. **`glab mr merge` default auto-merge** can turn an intended immediate merge into a queued one; always pass `--auto-merge=false` and verify `state==merged`.
6. **Approvals** are advisory on Free; merge safety must stay in the local gate (`detailed_merge_status`, `--sha`).
7. **Rate limit** introspection by headers only; limits on Free currently/proposed above; GraphQL limits undocumented.
8. **Quick actions** (`/close`, `/merge`, `/draft`, `/ready`) in note bodies execute; sanitize any generated text.
9. **Namespace depth**: `owner/repo` -> `group/subgroup/project`.
10. **Bot identity** `super-board-bot[bot]` -> dedicated user or access-token bot.
11. Flag clashes: glab `mr create -H` is head *repo*; `issue list` `-O/-F` swapped vs `mr list` `-F`.
